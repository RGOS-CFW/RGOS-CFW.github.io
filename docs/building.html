Building RG OS

Build options Build RGOS in GitHub Actions

Build options

On this pageHost requirementsEnvironment variablesImage sizePrebuilt coresBundled content 
sudo ./build.sh <device> [image|installer|update]

device is rg34xxsp, rg35xxh, rg35xxsp, rg-rotate, miniloong or all. With no device the script only prints usage. Output goes to out/; work files go to work/<device>/.

installer builds a first-boot installer image (out/<device>-rgos-installer.img): PortMaster, the libretro cores and the optional extras/ folder travel as a payload that the device installs on its first boot (INSTALLER.md).

The stock ROCKNIX image is cached in work/<device>/ and is not downloaded again on later builds. sudo ./build.sh update-img [device] (or ./build.sh <device> update-img) deletes the cached copy and downloads it again without building. Changing ROCKNIX_URL, ROCKNIX_H700_VERSION or H700_RAM selects a different cached file by name, so it downloads that one the first time.

Host requirements

Root (or sudo), and: debootstrap, losetup, mksquashfs/unsquashfs, wget, gunzip, md5sum, python3, readelf, sfdisk, truncate, plus sgdisk for the RG Rotate, mkfs.vfat and blkid for image and installer builds (shrinking the image; part of dosfstools / util-linux) and qemu-aarch64-static when the host is not arm64. On Debian/Ubuntu: apt install debootstrap qemu-user-static binfmt-support squashfs-tools wget gdisk dosfstools. Plan for tens of GB of disk and a long run (BUILD-WORKFLOW.md).

Pass variables through sudo with sudo -E, for example H700_RAM=DDR3 sudo -E ./build.sh rg35xxh.

Image size

The stock ROCKNIX image is a fixed ~2.2 GB however little is on it. Image and installer builds now shrink the result: unused stock files are dropped (PRUNE_ROCKNIX) and the card is laid out again with a FAT boot partition just big enough for its content plus BOOT_HEADROOM_MB (COMPACT_IMAGE). Whatever sits before partition 1 (U-Boot, SPL, partition table area) is copied unchanged and the later partitions are moved down. The ROMS partition is not part of the image: it is created on first boot in the free space, so a smaller image only means a smaller download and a faster write. Update tars are staged next to the old SYSTEM, so the default BOOT_HEADROOM_MB=auto leaves room for one (the size of SYSTEM plus 64 MiB). Set a number to choose the headroom yourself; reflashing needs none.

Prebuilt cores

Any aarch64 *_libretro.so placed in cores/ is copied into the image. dolphin_libretro.so, Dolphin's Sys data and its runtime libraries are removed again for the MiniLoong build (the only one without GameCube). The RG Rotate and the three H700 consoles (rg34xxsp, rg35xxh, rg35xxsp) keep them.

Building the cores: build-cores.sh

sudo ./build-cores.sh compiles the pre-installed emulator cores once, in an arm64 Debian builder, and keeps them in work/cores/. build.sh then uses them instead of compiling. 

sudo ./build-cores.sh                  # every core
sudo ./build-cores.sh flycast          # one core (several allowed: n64 psx)
sudo ./build-cores.sh --force psx      # rebuild even if nothing changed
sudo ./build-cores.sh --list           # list the core names
sudo ./build-cores.sh --clean          # wipe work/cores, cores-src and cores-logs

Updates only. Before building a core, the script checks upstream and skips the core when it is already up to date. It compares the latest upstream commit (a hash of the source tarball for ngp) and the build settings against a stamp saved in work/cores/.stamps/<core> after the last successful build. A core is rebuilt when:

  • upstream has a new commit,
  • its output is missing from work/cores/, or
  • its build settings changed: the repository URL, the make/cmake arguments (for example N64_MAKE_ARGS), the Flycast compiler flags (DC_OPT), or DEBIAN_SUITE.

Otherwise it prints up to date, not rebuilding and moves on. --force (or FORCE=1) rebuilds regardless. If upstream cannot be reached, an existing build is kept with a warning. A failed build removes its stamp, so it is retried on the next run. Only the main repository is checked, not its submodules, so use --force when a change is only in a submodule. Cores built before the stamps existed are rebuilt once on the first run. The final line lists which cores were built and which were skipped.

Bundled content

  • music/: launcher music baked into the image (LAUNCHERS-AND-THEMES.md).
  • config/: RetroArch configs, one per device family, and the RG OS gamepad autoconfig.
  • rgos/: the launcher, input hub, session scripts and tools.
  • initramfs/: the RG OS initramfs and extlinux patcher.
