Build RGOS in GitHub Actions

On this pageRun itRunner requirementsImportantBuilding locally

The workflow at .github/workflows/build-rgos.yml manually builds either a flashable disk image (.img) or an on-device update package (.tar) for the Anbernic RG34XXSP, RG35XX H, RG35XX SP, RG Rotate and MiniLoong Pocket 1 (build.sh: a Debian arm64 rootfs on each device's stock ROCKNIX image).

Run it

  1. Push this repository to GitHub with the workflow file included.
  2. Open Actions → Build RGOS image or update → Run workflow.
  3. Choose the device (rg34xxsp, rg35xxh, rg35xxsp, rg-rotate, miniloong or all) and img or update-tar. - img: artifact rgos-<device>-<id>-img containing <device>-rgos.img.gz (gunzip it, then flash). The run checks that partition 1 carries the RGOS label (renamed from the stock ROCKNIX), extlinux.conf has rdinit=/rgos-init, and then the device-specific part: RG Rotate = partition 3 is uboot (GPT); RG34XXSP = MBR image with dtb.img present; MiniLoong Pocket 1 = MBR image whose extlinux.conf loads miniloong.dtb. - update-tar: rgos-update-<device>-<id>.tar (manifest device is the one you chose: rg-rotate, rg34xxsp, rg35xxh or rg35xxsp or miniloong; SHA-256 checked). Tick update_extlinux to include extlinux.conf.
  4. For rg34xxsp, rg35xxh and rg35xxsp pick h700_ram (DDR4 default, DDR3 for consoles with LPDDR3; the stock U-Boot is RAM-specific, the wrong one is a black screen) and h700_panel (standard, or alt for the -v2-panel / -rev6-panel device tree). Both are ignored for rg-rotate. Optionally provide a build ID, turn off build_psx (skips the slow emulated PlayStation core build), turn off portmaster (builds without the preinstalled PortMaster, see docs/PORTS.md), turn off build_gc (skips the RG Rotate-only GameCube core, see docs/GAMECUBE.md) or override rocknix_url (not with device=all: each device has its own stock image).
  5. When the run succeeds, open its summary and download the artifact under Artifacts.

The workflow installs debootstrap, qemu-user-static and the partitioning tools, frees runner disk space, runs ./build.sh <device> image|update, and validates the result. Update tar files are checked against the SHA-256 hashes in manifest.json. Artifacts are retained for 14 days.

Runner requirements

The build is large and can take hours. GitHub-hosted runners have limited free disk space; the Debian rootfs plus the downloaded ROCKNIX image may exceed it. If a run fails with No space left on device or is killed for memory pressure, use a Linux self-hosted runner with substantial free disk space (suggested: 50+ GB free disk and 16+ GB RAM), or adapt the workflow to provision more storage.

Important

  • An .img is a whole-disk image intended to be flashed to an SD card; flashing overwrites the selected drive.
  • An update .tar is copied to the update/ directory on the ROMS partition. It is not a disk image.
  • The workflow runs only when manually started; it does not build on every push.

Building locally

./build.sh <rg34xxsp|rg35xxh|rg35xxsp|rg-rotate|miniloong|all> [image|update] from the repository root, using sudo when it is not already root. A device is required: sudo ./build.sh on its own only prints the usage text and does nothing. Output goes to out/ (rg34xxsp-rgos.img, rg-rotate-rgos.img); each device has its own work directory under work/<device>/. all builds the devices one after the other and needs roughly twice the disk space.

RG34XXSP specifics (see the header of build.sh): the base is the stock ROCKNIX H700 image (ROCKNIX-H700.aarch64-<release>-DDR4.img.gz from the ROCKNIX releases; H700_RAM=DDR3 / ROCKNIX_H700_VERSION=<tag> / ROCKNIX_URL=<url> change it). The image has an MBR, so there is no uboot partition and no SPL to flash; the build copies device_trees/sun50i-h700-anbernic-rg34xx-sp.dtb to dtb.img (RG34XXSP_DTB=sun50i-h700-anbernic-rg34xx-sp-v2-panel for the v2 panel) and then removes device_trees/, so dtb.img is the only device tree on the RGOS partition. The ROMS partition is created on first boot as partition 3.

RG35XX SP specifics: same stock ROCKNIX H700 image as the RG34XXSP and RG35XX H. The build copies device_trees/sun50i-h700-anbernic-rg35xx-sp.dtb to dtb.img (RG35XXSP_DTB=sun50i-h700-anbernic-rg35xx-sp-rev6-panel if the screen shows garbage; if the dtb name is not in the stock image the build stops and lists the ones that are). The screen is 640x480, so it uses the RG35XX H's 720x540 menu layout and startup video. It has no analog sticks (and no L2/R2 or L3/R3), so it does not share the RG34XXSP's / RG35XX H's input setup: the image carries its own config/retroarch-rg35xxsp.cfg (stick axes and L3/R3 unbound, fast-forward on MENU+UP and rewind on MENU+DOWN instead of the triggers) and /etc/rgos/input-rg35xxsp.json with "analog": false, so the input hub publishes no axes. It never falls back to the RG34XXSP's RetroArch config.

See also: BUILDING.md for all environment variables, UPDATES.md for installing an update tar.
