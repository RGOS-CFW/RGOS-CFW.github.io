Native Linux ports

On this pagePerformanceController mappingWhich controller ports seeQuitting a port

RG OS treats files discovered in roms/ports/ as native Linux ports. They are launched directly by rgos-launch; they do not need a RetroArch core or any other emulator.

  • .sh and .bash launchers are run with Bash when their shebang requests Bash, otherwise with sh. This works on exFAT ROMS cards where executable permission bits may not be preserved.
  • Any other file in roms/ports/ that is an ARM64 (aarch64) or 32-bit ARM Linux executable shows up as a port, whatever its name (game, game.aarch64, Game.arm64, game.bin): RG OS recognises it by its ELF header. Shared libraries (.so), data files and x86 programs are not listed. Put the binary directly in roms/ports/ (game data can sit in a sub folder next to it).
  • ROMS cards are FAT/exFAT and usually have no execute permission. RG OS tries to set it; if the card refuses, the binary is started through its dynamic loader (ld.so game), which only needs read access, so no chmod is needed.
  • The port's own libraries are found automatically: lib/, libs/, lib64/, libs.aarch64/, lib.aarch64/ (and libs.armhf/, lib32/ for 32-bit programs) next to the binary, plus PortMaster/libs, go on LD_LIBRARY_PATH. Before starting, missing libraries are listed by name on screen.
  • 32-bit ARM (armhf) programs need an armhf loader. The image is ARM64-only, so ship ld-linux-armhf.so.3 and the armhf libraries in libs.armhf/ next to the port; RG OS then uses them.
  • A wrong-CPU program (x86 / x86-64) or a file that is neither an executable nor a script gets a message that says so.
  • Extension-less scripts with a #! line are run with their interpreter.
  • The launcher's working directory is the directory containing the selected port, so relative asset paths used by common port launchers continue to work.
  • PortMaster comes preinstalled: the image carries a copy that is placed in ROMS/roms/ports/PortMaster on the first boot where that folder is missing, and PortMaster updates itself there. An existing install is never overwritten. Build with PORTMASTER=0 to leave it out, or PORTMASTER_ZIP=<file> to build offline.
  • PortMaster remains a separate Tools entry. PortMaster-installed ports are started through their installed launch scripts, allowing PortMaster to set up its own runtime and dependencies; RG OS does not wrap those games in RetroArch.

Console ROM folders continue to use the emulator/core configured for their system. See rgos-native.log on the device for native-port output when a port fails to start.

After every native port and every PortMaster run, rgos-launch also writes rgos-native.txt on the FAT boot partition: the command, exit code and run time, which helper tools are missing from the image, the port folder listing, kernel hints and the last 150 lines of rgos-native.log. Put the card in a PC and read it when a port closes by itself. (rgos-logs.txt is only written 8, 28 and 58 s after boot, so it never holds a port started later; a log that does not exist yet is shown as "not created yet".)

Performance

While a native port runs, RG OS switches the CPU and GPU/DDR governors to performance and restores them when the port exits, and the port runs at a raised scheduling priority. To change the governor, put its name in rgos-governor.txt on the boot partition (default keeps the stock governor).

Controller mapping

SDL ports only treat a joystick as a game controller when a controller database entry matches it, so rgos-launch gives every native port (and PortMaster) a mapping for the built-in "RG OS Gamepad". It is exported as SDL_GAMECONTROLLERCONFIG, and also written to /run/rgos/gamecontrollerdb.txt (SDL_GAMECONTROLLERCONFIG_FILE) for launchers that replace the variable.

Layout (positional, like an Xbox pad): A bottom, B right, X left, Y top, L1/R1 shoulders, L2/R2 triggers, Select = back, Start, Menu = guide, L3/R3 stick clicks, d-pad. The sticks are included only when analog sticks are enabled in /etc/rgos/input.json or the per-device /etc/rgos/input-<device>.json (which wins, as for the input hub; the build sets it per device). The Settings > Swap A / B option applies before SDL sees the pad, so ports follow it automatically.

To change the mapping, add lines in SDL_GameControllerDB format to rgos-gamecontrollerdb.txt:

  • ROMS/ports/rgos-gamecontrollerdb.txt applies to every port.
  • rgos-gamecontrollerdb.txt next to a port applies to that port only and wins.

A line with the same GUID replaces the built-in mapping; the GUID is the first field of the generated /run/rgos/gamecontrollerdb.txt. Lines starting with # are ignored. A mapping already exported in SDL_GAMECONTROLLERCONFIG wins over all of these.

Which controller ports see

The input hub grabs the console's raw gamepad and exposes only the virtual "RG OS Gamepad". Because the image runs no udev, the hub also removes the raw pad's /dev/input/eventN node while it is running (it keeps the device open itself), so SDL ports see exactly one controller, the working one. The node is put back when the hub stops, and at the next hub start if the hub was killed. Look for hid /dev/input/eventN from SDL ports in rgos-input.log.

Quitting a port

Hold Select + Start for about 2 seconds to stop the running native port and return to the menu. RG OS sends the port's whole process group SIGTERM, then SIGKILL after 3 seconds if it has not exited. The stop is logged in rgos-native.log and is not reported as an error. This also works inside PortMaster. Ports run in their own session so child processes stop with them.
