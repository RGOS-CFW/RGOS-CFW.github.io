Install guide

On this pageWhat you needPick the imageDevice specificsFlashFirst bootAdd gamesUpdatingIf it does not boot

A step-by-step guide to putting RG OS on a microSD card and booting it for the first time. It is the same for every supported device except for a few things to check first, which are called out in step 2.

What you need

  • A supported console: RG34XXSP, RG35XX H, RG35XX SP, RG Rotate or MiniLoong Pocket 1.
  • A microSD card. 16 GB or more is sensible; the rest of the card becomes your ROMS partition.
  • A PC with a card reader and a flashing tool: balenaEtcher, Raspberry Pi Imager, or dd on Linux and macOS.
  • An RG OS image for your device, either from a release or built yourself (Build options, Build RGOS in GitHub Actions).
  • For the RG Rotate only: a USB-A to USB-C cable, for flashing the SPL.
Back up the card first. Flashing erases everything on it.

1. Pick the right image

Every device has a normal image and an installer image. Both end up with the same RG OS; they differ in what happens on the first boot.

DeviceNormal imageInstaller imageCheck first
RG34XXSP rg34xxsp-rgos.img rg34xxsp-rgos-installer.img RAM type (DDR4 or DDR3) and panel revision
RG35XX H rg35xxh-rgos.img rg35xxh-rgos-installer.img RAM type (DDR4 or DDR3) and panel revision
RG35XX SP rg35xxsp-rgos.img rg35xxsp-rgos-installer.img RAM type (DDR4 or DDR3) and panel revision
RG Rotate rg-rotate-rgos.img rg-rotate-rgos-installer.img Flash the SPL once from a PC (guide)
MiniLoong Pocket 1 miniloong-rgos.img miniloong-rgos-installer.img Nothing; boots straight from the card
  • Normal image (<device>-rgos.img): boots into RG OS, creates the ROMS partition automatically as exFAT, and copies PortMaster on first boot.
  • Installer image (<device>-rgos-installer.img): shows an RG OS Installer screen on first boot where you choose the ROMS file system (FAT32, exFAT or ext4), then installs the cores and PortMaster. See First-boot installer.

If you are unsure, use the normal image. If the file ends in .img.gz, decompress it first.

2. Check your device first

RG34XXSP, RG35XX H and RG35XX SP

The U-Boot on the card is built for one RAM type, and the device tree is chosen for one panel revision. The default image is DDR4 with the standard panel. If your console is DDR3, or has the newer panel (-v2-panel on the RG34XXSP, -rev6-panel on the RG35XX H and SP), the image has to be built for it, or the screen stays black. Your device page explains how: RG34XXSP, RG35XX H, RG35XX SP.

RG Rotate

Flash the replacement SPL once, from a PC, before you boot the card for the first time. The steps, and how to restore the stock SPL, are in RG Rotate: flashing the SPL.

MiniLoong Pocket 1

Nothing to prepare. It boots straight from the card and leaves the internal Android untouched. See MiniLoong Pocket 1.

3. Flash the card

  1. Put the card in your PC. Decompress the image if it is .img.gz.
  2. Write the .img to the whole card, not to a partition.
    • balenaEtcher / Raspberry Pi Imager: choose the image, choose the card, flash.
    • Linux / macOS with dd: find the card's device name first (lsblk on Linux, diskutil list on macOS); writing to the wrong disk destroys its data.
  3. Eject the card cleanly. An unclean eject is a common cause of a card that does not boot.
sudo dd if=rg35xxh-rgos.img of=/dev/sdX bs=4M conv=fsync status=progress
sync

Replace rg35xxh-rgos.img with your image and /dev/sdX with the card (for example /dev/sdb, never a partition such as /dev/sdb1).

4. First boot

Fully power the console off first if it was running another system, insert the card and power on.

Normal image

  • rgos-roms creates the ROMS partition in the free space (exFAT; partition 3 on the H700 consoles and the Pocket 1, partition 4 on the RG Rotate). The old partition table is backed up to the boot partition first, and a card whose layout it does not recognise is left alone.
  • PortMaster is copied to roms/ports/PortMaster if that folder is missing.
  • The startup splash plays once at power on.

Installer image

  1. The RG OS Installer screen appears with Install and Power off. Use the D-pad to choose and A to confirm.
  2. Choose Install, then pick the ROMS file system: FAT32, exFAT (default, recommended) or ext4. B goes back without changing anything.
  3. The installer partitions the card, installs the cores and PortMaster, then restarts into RG OS by itself.
Do not switch the console off while an install is running. If it fails, the screen stays up with the reason: A retries, B starts RG OS without finishing, and the installer runs again on the next boot.

5. Add games

The short version is below; the full guide is Add games.

  1. Put the card back in your PC. Copy ROMs into the folders under roms/ on the ROMS partition, one folder per system: for example roms/gba/, roms/snes/, roms/psx/.
  2. Back on the console, press X in the launcher to rescan. Systems with no games and no installed core are hidden.

The folder for each system is listed in Supported systems, BIOS files in BIOS files, and the rest of the card in SD card layout. Once Wi-Fi is set up you can also copy files over the network (Wi-Fi, Bluetooth and SSH). RG OS does not provide games or BIOS files.

6. Optional first steps

  • Settings > Missing BIOS check lists the BIOS files your systems still need.
  • Settings > Wi-Fi, then Settings > Game artwork for cover art (Game artwork).
  • Settings > Theme and Settings > Launcher to change the look (Launchers, themes, splash and music).
  • Settings > Swap A / B buttons if confirm and back feel reversed.
  • More cores: Tools > Core Installer (Core Installer).

Updating later

You do not need to reflash to update. Put an rgos-update-<device>-<id>.tar in the update/ folder on the ROMS partition and boot; your games, saves and settings are never touched. Changing the RAM type or panel of an H700 console is the exception and needs a new image. See Offline updates.

If it does not boot

Put the card in a PC and look at the small FAT boot partition (the one labelled RGOS). RG OS leaves evidence files there; which ones exist tells you how far the boot got.

SymptomMost likely cause
H700 console: black screen, no rgos-initramfs.txtWrong RAM type. Rebuild with the other one (details).
H700 console: black or garbled screen, rgos-initramfs.txt existsWrong panel revision. Rebuild with the alternate device tree.
RG Rotate boots AndroidThe SPL was not flashed, or partition 3 is not the uboot partition, or U-Boot could not load the initrd (details).
MiniLoong Pocket 1: black screenThe FDT line in extlinux/extlinux.conf does not name miniloong.dtb (details).
Any device: card does not boot at allCard not ejected cleanly after flashing; flash it again.

Full explanations are in Troubleshooting, and the files to collect when asking for help are in Logs and diagnostic files.
