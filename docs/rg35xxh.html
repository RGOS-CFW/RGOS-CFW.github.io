RG35XX H

On this pageBuildRAM and panelFlash and first bootControlsDisplayHDMIUpdatesTroubleshooting

The Anbernic RG35XX H is an Allwinner H700 handheld with a 640x480 screen. It shares its base image, bootloader approach and build options with the other two H700 consoles.

Argumentrg35xxh
/etc/rgos-devicerg35xxh
SoCAllwinner H700
Screen640x480
Menu layout720x540 layout, with its startup video (shared with the RG35XX SP)
Base imageROCKNIX-H700 (ROCKNIX-H700.aarch64-<release>-DDR4.img.gz)
Partition tableMBR; no uboot partition, no SPL to flash
ROMS partitioncreated on first boot as partition 3
Device treedtb.img (copied from sun50i-h700-anbernic-rg35xx-h.dtb)
Imagerg35xxh-rgos.img

Build

sudo ./build.sh rg35xxh            # SD card image   -> out/rg35xxh-rgos.img
sudo ./build.sh rg35xxh installer  # first-boot installer image -> out/rg35xxh-rgos-installer.img
sudo ./build.sh rg35xxh update     # offline update tar -> out/rgos-update-rg35xxh-<id>.tar
H700_RAM=DDR3 sudo -E ./build.sh rg35xxh   # DDR3 console
RG35XXH_DTB=sun50i-h700-anbernic-rg35xx-h-rev6-panel sudo -E ./build.sh rg35xxh   # rev6 panel

Other options: ROCKNIX_H700_VERSION=<release tag> and ROCKNIX_URL=<image .img.gz>. See Build options.

RAM type and panel revision

Two independent choices decide whether the screen works on this console. Both are made when the image is built, because the U-Boot and the device tree are written to the card then.

  1. RAM type: DDR4 (default) or DDR3. The U-Boot on the card is built for exactly one of them. A mismatch is a black screen with nothing written to the card.
  2. Panel revision: the standard device tree (sun50i-h700-anbernic-rg35xx-h) or the alternate one (sun50i-h700-anbernic-rg35xx-h-rev6-panel, the rev6 panel). A wrong choice gives a black or garbled screen, but the card still boots far enough to write rgos-initramfs.txt. 
H700_RAM=DDR3 sudo -E ./build.sh rg35xxh
RG35XXH_DTB=sun50i-h700-anbernic-rg35xx-h-rev6-panel sudo -E ./build.sh rg35xxh

In the GitHub workflow these are the h700_ram and h700_panel inputs (standard or alt); see Build RGOS in GitHub Actions. If you do not know which combination your console needs, try the four combinations. The card's rgos-image-info.txt says which RAM type an image was built for. The build copies the chosen tree to dtb.img, which is the only device tree on the boot partition.

Flash and first boot

  1. Flash rg35xxh-rgos.img to the whole card (not to a partition) with balenaEtcher, Raspberry Pi Imager or dd, then eject it cleanly.
  2. Insert the card and power on. On the first boot rgos-roms creates the ROMS partition (partition 3, exFAT) in the free space on the card. The old partition table is backed up to the boot partition first.
  3. Copy ROMs into roms/<system>/ on the ROMS partition and press X in the launcher to rescan.

The full walkthrough is in Getting started; the first-boot installer image is described in First-boot installer.

Controls and input

The RG35XX H has analog sticks, L2/R2 and L3/R3, enabled by /etc/rgos/input-rg35xxh.json. The standard launcher buttons and RetroArch hotkeys apply, including Menu + R2 (hold) for fast-forward. See Controls and hotkeys.

Display and performance

The 640x480 screen uses the 720x540 menu layout; the launcher scales only the rows that changed each frame. Heavier systems such as N64 and Saturn will not reach full speed in every game on this console. See Supported systems and Launchers, themes, splash and music.

Mini-HDMI output

Mini-HDMI is supported on this console. It is selected at boot: power off before connecting or disconnecting the cable, then boot again. The default resolution cap is 720p. See Mini-HDMI output.

Offline updates

An update tar built with ./build.sh rg35xxh update only installs on this device (its manifest must match /etc/rgos-device, which is rg35xxh). The device tree is dtb.img; add it to the tar with UPDATE_DTB=1. Updates never replace the U-Boot already on the card, so changing the RAM type or the panel needs a new image. See Offline updates.

Troubleshooting

  • Black screen, no rgos-initramfs.txt on the boot partition. The console never reached Linux. The usual cause is the wrong RAM type; rebuild with H700_RAM=DDR3 sudo -E ./build.sh rg35xxh (or the reverse). Also re-flash if the card was not ejected cleanly.
  • Black or garbled screen, but rgos-initramfs.txt exists. The panel revision is wrong; rebuild with RG35XXH_DTB=sun50i-h700-anbernic-rg35xx-h-rev6-panel (rev6 panel). Fully power off (10 s power hold) before trying a new card.
  • No Bluetooth adapter found. The H700 consoles use a Realtek RTL8821CS whose Bluetooth half sits on a UART. The rgos-bt: lines in rgos-logs.txt (or python3 /opt/rgos/btctl.py diag over SSH) show which step fails.

The full tables are in Troubleshooting and Logs and diagnostic files.
