Which cores ship in the image

build.sh installs these Debian libretro packages: gambatte, mgba, snes9x, nestopia and beetle-wswan. It also builds, best effort, the PlayStation core (pcsx_rearmed), Genesis Plus GX, the Neo Geo Pocket core the three Atari cores (stella2014 for the 2600, atari800 for the 5200, prosystem for the 7800), Flycast, Mupen64Plus-Next and YabaSanshiro (Saturn) from source, the two PICO-8 cores (fake-08 and retro8), MAME 2003-Plus (mame2003_plus, the arcade core), plus Dolphin on the RG Rotate and the H700 consoles. A failed source build is reported with a !! line and the image is built without that core.

Systems that the build does not provide a core for only appear when you supply the core yourself: put a prebuilt aarch64 <name>_libretro.so in cores/ before building, or install a Debian package with EXTRA_PKGS (BUILDING.md). The menu lists a system only when a compatible core is present. FinalBurn Neo (fbneo) and current MAME (mame) are not built into the image; see Arcade and Neo Geo below.

Arcade and Neo Geo (FinalBurn Neo, MAME)

Put ROM sets in roms/arcade/ (and roms/neogeo/ for Neo Geo) on the ROMS card, which is /media/roms/roms/arcade/ on the console. There is no separate folder per core: arcade and neogeo can each run fbneo, mame2003_plus or mame, and you pick the core per system in Settings > Emulators. The default is fbneo. Keep ROM sets zipped (.zip or .7z), and put neogeo.zip in bios/ for Neo Geo (BIOS files).

  • mame2003_plus is built into the image (best effort, from source). If that build fails, the image has no arcade core until you add one.
  • fbneo is the default core but is not built into the image. Install it with Tools > Core Installer, or put an aarch64 fbneo_libretro.so in cores/.
  • mame (current MAME) is not built into the image because it is too heavy to build there. Install it with the Core Installer, or put a prebuilt aarch64 mame_libretro.so in cores/.
  • ROM sets are version specific. A set built for FinalBurn Neo does not always run in MAME 2003-Plus or current MAME; if one core fails to load a game, check that the set matches that core.

NES / Famicom (RetroArch + Nestopia core)

On every supported device NES runs through RetroArch with the Nestopia libretro core, installed from the Debian libretro-nestopia package (EMU_PKGS in build.sh). Settings > Emulators offers whichever other NES core is installed (fceumm, quicknes, mesen).

  • ROMs: <ROMS>/roms/nes/*.nes (also .unf, .unif).
  • Famicom Disk System: .fds games plus disksys.rom in <ROMS>/bios/ (BIOS.md).
  • Saves: <ROMS>/saves/nes/, states: <ROMS>/states/nes/.
  • Your own RetroArch overrides: <ROMS>/config/retroarch.cfg (appended last, wins over everything).
  • Hotkeys while playing: CONTROLS.md.

Nintendo 64

build.sh builds Mupen64Plus-Next (mupen64plus_next) as an OpenGL ES core, for the same reason as Flycast below: RetroArch on this image is a GLES build and a desktop-OpenGL core closes right after launch. N64_REPO=none skips it, N64_MAKE_ARGS changes the make arguments (default platform=unix FORCE_GLES=1; the ARM64 dynarec is picked automatically on aarch64) and N64_REQUIRED=1 stops the build when the core fails to build. The image's own core is looked up before the one on the ROMS card. ParaLLEl N64 (parallel_n64) is listed as an alternative core and can be added with Tools > Core Installer or by putting a GLES build in cores/.

Put ROMs in roms/n64/ as .z64, .n64 or .v64 (any byte order works), or .ndd for 64DD disks. No BIOS is needed. The system runs with the CPU and GPU clocks pinned to performance while a game is running. Many games need the right stick: turn on DPAD to joystick (SETTINGS.md) if your console has no sticks. Speed varies a lot between games and consoles; the RG35XX H and similar H700 consoles will not run every title at full speed. The video driver can be forced with retroarch-n64-video.txt (SD-CARD-LAYOUT.md).

Launch profile. RG OS supplies a conservative GLideN64 profile for the Mali-G31: dynamic-recompiler CPU, HLE RSP, 320x240 for 4:3 and 640x360 for 16:9, no MSAA, and the more costly framebuffer, shader-storage and threaded-renderer features disabled. If the normal launch fails immediately, RG OS retries with the cached interpreter. These settings are generated for each launch; optional user overrides belong in config/n64-options.cfg on the ROMS card.

Nintendo GameCube (RG Rotate and H700 consoles)

GameCube runs through RetroArch with the Dolphin libretro core (dolphin_libretro.so). It is built from source (GC_REPO, default https://github.com/libretro/dolphin.git) when building rg-rotate, rg34xxsp, rg35xxh or rg35xxsp. The miniloong build never compiles or ships it, and menu.py hides the system there. The H700 consoles (four Cortex-A53 cores, Mali-G31 MP2) are far weaker than the RG Rotate: expect light games to run well and heavy ones to run slowly.

GameCube only, no Wii. The Dolphin core can technically run both, so there is no Wii menu entry, no roms/wii folder, and .wbfs/.wad are not accepted. Wii games placed in roms/gc are not supported (.iso is shared by both consoles, so keep Wii dumps out of that folder).

  • ROMs: <ROMS>/roms/gc/*.gcm, .iso, .gcz, .rvz, .ciso, .m3u, .dol, .elf.
  • Saves: <ROMS>/saves/gc/, states: <ROMS>/states/gc/.
  • Dolphin's Sys data folder is shipped in the image and copied once to <ROMS>/bios/dolphin-emu/Sys on the first GameCube launch.
  • Optional GameCube BIOS (boot logo): IPL.bin in <ROMS>/bios/dolphin-emu/Sys/GC/<USA|EUR|JAP>/.

Build options

sudo ./build.sh rg-rotate          # includes the GameCube core
sudo ./build.sh rg35xxsp           # so do rg34xxsp and rg35xxh
GC_REPO=none sudo -E ./build.sh rg-rotate   # skip it (faster build)

A prebuilt aarch64 dolphin_libretro.so in cores/ is used instead of building (and is deleted again for the MiniLoong build). In GitHub Actions use the build_gc checkbox.

The build is best-effort, like the other source-built cores: if it fails, a !! line is printed and the image is built without GameCube. It is slow under qemu emulation (plan on a long run).

Runtime dependency fix

The Dolphin core may fail to load with liblzo2.so.2: cannot open shared object file when a prebuilt dolphin_libretro.so is used. RG OS now includes Debian's liblzo2-2 runtime package in the base image so this dependency is present even for prebuilt cores. Rebuild the image or install liblzo2-2 on an existing Debian-based RG OS image.

Performance tuning

Every GameCube launch gets a tuned set of Dolphin core options, written to /run/rgos/dolphin-options.cfg and handed to RetroArch (core_options_path). They target the RG Rotate's Mali-G52 GPU, which is the usual bottleneck (the H700 consoles get a lighter variant, see below):

  • Native resolution (dolphin_efb_scale = x1). The biggest single speed-up; raise it only for light games.
  • ARM64 JIT CPU core (JITARM64) + fastmem, DSP HLE (the x86-only JIT64 and DSP JIT are never requested on aarch64), GPU-side EFB copies, no forced texture filtering.
  • A-sync ubershaders, so a new effect never freezes the game while its shader compiles. The first minutes of a game can still hitch a little while the shader cache fills; it gets smoother with play.
  • Frame pacing. GameCube launches turn on adaptive vsync, a third swapchain image and a larger audio buffer, so a game that runs at 50-58 fps no longer drops to 30 fps or crackles. The CPU and GPU governors are already set to performance for GameCube (see /boot/rgos-governor.txt).
  • Accuracy features off. MMU emulation, anisotropic filtering, custom textures, widescreen and the Dolphin on-screen display are disabled; almost no GameCube game needs them and they cost CPU or GPU time.
  • RetroArch extras off. Rewind, run-ahead, shaders, bilinear smoothing, frame delay and the threaded video driver are turned off for GameCube. A line in <ROMS>/config/retroarch.cfg still overrides any of them.
  • Persistent shader cache. Compiled shaders of every hardware-rendered system (GameCube, Dreamcast, N64, Saturn) are kept in <ROMS>/config/mesa-cache (up to 256 MB) instead of RAM, so a game does not recompile them after every boot. If the card is not writable it falls back to /tmp.
  • H700 consoles. On the RG34XXSP, RG35XX H and RG35XX SP shaders compile with plain a-sync instead of ubershaders (too heavy for the Mali-G31) and the audio buffer is 128 ms. Override either in dolphin-options.cfg.
  • Safe retry. If a game dies within 30 s, the retry also turns fastmem off and uses the cached interpreter. This retry also happens when a video driver is pinned in /boot/retroarch-gc-video.txt.

To change any option, create <ROMS>/config/dolphin-options.cfg with lines such as: 

dolphin_efb_scale = "x2 (1280 x 1056)"
dolphin_shader_compilation_mode = "sync UberShaders"
dolphin_fastmem = "disabled"

Your lines win over the built-in ones, including in the retry. Remove the file to go back to the defaults. A prebuilt dolphin_libretro.so is unaffected by the build flag; a core built by build.sh is compiled with -mtune=cortex-a75.

If a GameCube game closes right after launching

RG OS now does these things itself; each one was a way for the game to "just close" without a message:

  • Dolphin Sys folder. A half-copied <ROMS>/bios/dolphin-emu/Sys (interrupted copy, or the exFAT card refusing file permissions) used to count as done forever. Now a stamp file is written only after a complete copy, so an incomplete folder is finished on the next launch and a new image build refreshes the shipped files. Your own files (IPL.bin) are left alone.
  • Missing libraries. Before starting, the launcher runs ldd on the core and, if a library is missing, shows its name instead of closing. build.sh does the same check at build time for rg-rotate and tries to install what is missing.
  • Video driver. Dolphin needs a real GL context. GameCube launches pin RetroArch to glcore and, if that dies within 30 s, retry once with gl. To force one driver, put one word (glcore, gl, vulkan) in /boot/retroarch-gc-video.txt.
  • A readable report. GameCube launches always use RetroArch's verbose log. After every launch /boot/rgos-retroarch.txt (on the FAT partition, readable on a PC) holds the command, the missing libraries (if any), the log of every attempt, the exit code or the signal that killed it (for example SIGSEGV), and kernel lines about segfaults, out-of-memory kills and GPU errors.

If it still closes, send rgos-retroarch.txt and rgos-logs.txt from the boot partition.

See also: BIOS.md, LOGS.md.

Saturn

Put discs in roms/saturn/ (.cue with its .bin tracks next to it, .chd, .iso, .mds, or .m3u for multi-disc games). The image has exactly one Saturn core pre-installed, YabaSanshiro (the best fit for ARM handhelds), built by build.sh from SATURN_REPO (SATURN_REPO=none skips it, SATURN_MAKE_DIR / SATURN_MAKE_ARGS change the build, SATURN_REQUIRED=1 stops the build when it fails). The alternatives, Yabause and Beetle Saturn, are not in the image: install them from Tools > Core Installer, or drop a <name>_libretro.so into cores/ on the ROMS card, then pick one in Settings > Emulators. If the YabaSanshiro build fails, the image has no Saturn core and the Saturn menu entry stays hidden until you install one. The CPU and GPU clocks are pinned to performance while a game runs. BIOS files are listed in BIOS.md.

Saturn core profiles. YabaSanshiro uses frameskip, the SH-2 dynamic recompiler and original-resolution rendering; its compute-shader path is disabled by default. If bios/saturn_bios.bin is absent, RG OS explicitly selects its HLE BIOS. Yabause has its own option namespace, with frameskip and two rendering threads by default (one thread on a safe retry), and also falls back to HLE when its optional BIOS is absent. Beetle Saturn is software-rendered: RG OS does not force the GLES hardware video driver or apply YabaSanshiro options to it. Beetle instead needs a supported regional BIOS. Per-core overrides can be placed in config/saturn-options.cfg; only options belonging to the selected core are passed through. See BIOS files for the BIOS requirements.

Dreamcast

build.sh builds Flycast as an OpenGL ES core (DC_REPO=none skips it; DC_MAKE_ARGS changes the make arguments). RetroArch on this image is a GLES build, and the libretro buildbot Flycast (what Tools > Core Installer downloads) is desktop-OpenGL only: it closes right after launch with Requesting OpenGL context, but RetroArch is compiled against OpenGLES. The image's own core is looked up before the one on the ROMS card, so it wins. Without a GLES Flycast, put one in cores/ on the ROMS card (it must be built with FORCE_GLES=1).

Performance tuning. The libretro Flycast core starts with settings picked for these small GPUs: 640x480, threaded rendering, fast alpha sorting, mipmapping and anisotropic / PVR2 filtering off, GD-ROM fast loading, auto frame skip and DSP off (a few games lose reverb-type effects), plus adaptive vsync, a 3-image swapchain and a larger audio buffer. If dc_boot.bin is not in bios/ (or bios/dc/), Flycast's HLE BIOS is used. To change any of it, put reicast_... lines in <ROMS>/config/flycast-options.cfg; they win over these defaults. If Flycast dies right after launch, RG OS retries once with threaded rendering and auto frame skip turned off. The core itself is compiled with -O3 -mtune=cortex-a55 (DC_OPT, see Building).

Standalone Flycast. Besides the libretro core, Dreamcast can run the standalone Flycast emulator. It shows up as Flycast (standalone) in Settings > Emulators once a flycast executable is found in /usr/local/bin, /usr/bin, /opt/flycast or cores/standalone/ on the ROMS card; the libretro core stays the default until you pick it. RG OS starts it itself (no RetroArch): the game's file is passed on the command line, Select + Start held stops it like a native port, and its output goes to rgos-native.log / rgos-native.txt. Its settings live on the ROMS card in config/flycast/ (data in config/data/flycast/), and bios/dc/ is linked in as its BIOS folder, so the BIOS Manager files are shared. RetroArch features (RetroArch's own menu, its save states, overlays and retroarch.cfg overrides) do not apply to it; use Flycast's own settings. build.sh builds it from DC_REPO as an OpenGL ES program and installs /usr/local/bin/flycast (DC_STANDALONE=0 skips it, DC_SA_CMAKE_ARGS adds CMake arguments, DC_SA_REQUIRED=1 stops the build when it fails). It is not on the Core Installer list: a program cannot be fetched from the libretro buildbot, so to add your own build put a GLES flycast executable in cores/standalone/. RG OS checks the known executable locations, validates that the file is executable, launches it directly with the selected disc, and restores the performance governor when it exits. A missing or failing executable produces an error instead of silently treating it as a libretro core. Standalone diagnostics are written to rgos-native.txt and /var/log/rgos-native.log.

Standalone performance tuning. The first time the standalone emulator starts, RG OS writes the same low-cost settings the libretro core uses into config/flycast/emu.cfg: 640x480, threaded rendering, fast alpha sorting, no mipmaps, no anisotropic filtering, no texture upscaling, auto frame skip for late frames, DSP off, dynarec and idle-skip on. They are applied once per tuning version, so changes you make later in Flycast's own menu are kept. Lines in <ROMS>/config/flycast-standalone.cfg (key = value, same names as in emu.cfg) are applied on every launch and win. The standalone launch also enables threaded Mesa GL dispatch (mesa_glthread) and uses the persistent shader cache in <ROMS>/config/mesa-cache. Flycast ignores keys it does not know, so check a name against the emu.cfg that Flycast writes after you change that setting in its menu.

Put discs in roms/dreamcast/, one folder per game is fine. Use .gdi (keep its track files next to it), .cdi, .chd, or .cue/.m3u for multi-disc games. Only the disc file is listed, not the track files. The system runs with the CPU and GPU clocks pinned to performance while a game is running, and it is demanding: on the RG35XX H and similar H700 consoles many games will not reach full speed. A real BIOS is optional (BIOS.md).

PICO-8

PICO-8 is a fantasy console, so there is no hardware to dump: games are carts, either a text .p8 file or a .p8.png picture with the game hidden inside it (the format used by the PICO-8 BBS and itch.io). Put them in roms/pico8/. Both kinds show in the Games list; a plain .png next to them is ignored, and a game.p8.png is listed as game (its artwork is artwork/pico8/game.png).

The image carries two open-source libretro cores, both built by build.sh and both best effort: fake-08 (fake08, the default, written for low-power handhelds) and retro8 (retro8, an alternative to try when a cart misbehaves). Pick between them in Settings > Emulators, or fetch either from Tools > Core Installer if the build of one failed. PICO8_REPO / PICO8_ALT_REPO change the sources (none skips that core, both none skips PICO-8), PICO8_MAKE_DIR / PICO8_MAKE_ARGS change how fake-08 is built and PICO8_REQUIRED=1 stops the build when neither core builds (BUILDING.md). If both fail, the PICO-8 entry stays hidden until you install a core.

RG OS strips both extensions from a .p8.png cart when displaying its game title and matching artwork, so Celeste.p8.png appears as Celeste. If the normal core table cannot be loaded, the launcher still has a PICO-8 fallback: fake08 first, then retro8 as the compatible alternative.

No BIOS is needed and the official Lexaloffle PICO-8 program is not used, so nothing is installed from lexaloffle.com. Both cores re-implement the PICO-8 API themselves, so a few carts that lean on rarely used features can run differently from the real console; if one does, try the other core. PICO-8 only has a D-pad and two action buttons (O and X) plus Start/Select, so the console's normal button layout applies. Carts that need a keyboard or mouse cannot be used without one.

Recent launch notes

  • N64 has a GLES-specific launch profile and a conservative retry path; see the N64 section above.
  • Saturn options and BIOS handling are selected per core, rather than mixing YabaSanshiro, Yabause and Beetle settings.
  • Dreamcast standalone Flycast is a native executable, not a RetroArch core; its settings persist on the ROMS card.
  • PICO-8 recognizes both .p8 and .p8.png cartridges and cleans up double-extension titles.

Choosing another core

Settings > Emulators lists each system and the installed cores that are compatible with it. Compatible alternatives include, for example, gpsp / vbam for GBA, sameboy for Game Boy, fceumm / quicknes / mesen for NES, bsnes variants for SNES, picodrive for Sega systems, and swanstation / mednafen_psx for PlayStation, and retro8 for PICO-8. Only cores that are actually installed appear. Tools > Core Installer downloads the ones you do not have yet (CORE-INSTALLER.md).

Multi-disc games

Use an .m3u playlist for PlayStation, Sega CD and GameCube multi-disc games, and keep the playlist next to the disc images. Prefer .chd over a pile of .bin / .cue files.

Notes

  • .bin is shared by Genesis, 32X, Pico and Atari systems. Keep each system's files in its own folder.
  • .iso is shared by Sega CD, PlayStation and GameCube. Keep Wii dumps out of roms/gc; Wii is not supported.
  • Many systems need BIOS files (BIOS.md).
  • System-specific notes: NES / Famicom, GameCube, PORTS.md.

Dreamcast says Requesting OpenGL context, but RetroArch is compiled against OpenGLES? The flycast_libretro.so on the ROMS card is a desktop-GL build. The image build had no GLES Flycast to ship (see flycast-build.log in the build work folder; DC_REQUIRED=1 stops the build when that happens), and the Core Installer no longer downloads the buildbot Flycast. Delete cores/flycast_libretro.so from the card, fix the build error and rebuild, or put a FORCE_GLES=1 build in cores/.
